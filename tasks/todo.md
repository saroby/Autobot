# clone 스킬 한방 실행 (one-shot) 만들기

## 목표

`/autobot:clone <앱>` 한 번으로 기기 게이트 → 앱 전체 탐험 → 측정 → 스펙/코드 → 렌더·대조까지
사람 개입 없이 진행한다. 모델이 저작해야 하는 두 산출물(화면 스펙 `.md`, SwiftUI 뷰)만 모델이 쓰고,
그 앞뒤의 기계적 단계는 각각 한 명령으로 닫는다.

## 확인 결과 (수정 전 상태 = 한방 불가)

- 오케스트레이터 부재: 스킬이 10단계 수동 절차. 단일 진입 명령이 없다.
- `device_wda.sh explore` 는 **현재 화면의 frontier 만** 소진하고 "다른 화면으로 이동한 뒤 다시 실행"으로 끝난다
  (`scripts/device_wda.sh:1585`). 화면 간 이동은 사람/모델이 손으로 한다.
- `device_flow.py next` 는 미탐험 화면을 나열만 하고 **경로를 주지 않는다** (`scripts/device_flow.py:334`).
- 문서상 사람 게이트 4곳: Step 2a(더 탐험할지 결정), Step 2c(재현 화면 고르기),
  Step 5(`views.json` 수동 검토), Step 2(데이터 필요 화면에서 사용자에게 생성 요청).
- Step 6 검증이 화면마다 `<NN>` 자리표시자 명령 수동 반복. 배치 루프가 없다.

## 체크리스트

- [x] `device_flow.py next-tap <flow.jsonl> <fresh_tree.xml>` — 이 화면의 미탐험 후보, 없으면
      미탐험 화면까지의 최단 관찰 경로 첫 홉을 **fresh tree 좌표로** 한 개 낸다. 전역 소진이면 그렇게 말한다.
- [x] `cmd_explore` 루프를 `todo` → `next-tap` 으로 교체. 전역 소진에서만 정상 종료.
      routing 홉 연속 한도로 ping-pong 중지.
- [x] `scripts/clone_run.sh observe` — workspace → device → bundle 해석 → doctor → session →

- [x] `scripts/clone_run.sh verify` — `views.json` 의 화면마다 render → structural diff → compare.
      누락이 있으면 non-zero.
- [x] SKILL.md / commands/clone.md 를 한방 기본 경로로 재작성. 사람 게이트는 삭제가 아니라

## Working Notes

  경계는 반드시 실제 산출물로 교차 검증한다. 픽스처 단독 테스트는 이 실패를 못 잡는다.

## Results

### 확인 (수정 전)

한방 실행은 **불가능했다**. 근거 네 가지:

1. 오케스트레이터가 없었다 — 스킬이 Step 0~6 을 사람/모델이 손으로 잇는 절차였다.
2. `device_wda.sh explore` 가 **한 화면의 frontier 만** 소진하고 "다른 화면으로 이동한 뒤 다시 실행하라"로 끝났다. 앱 전체 탐험에는 화면마다 사람의 이동이 필요했다.
3. 문서상 사람 게이트 4곳(Step 2a 추가 탐험 결정, Step 2c 재현 화면 선택, Step 5 `views.json` 검토, Step 2 데이터 필요 화면 요청)이 모두 실행을 막았다.
4. Step 6 검증이 화면마다 `<NN>` 을 갈아 끼우는 세 명령의 수동 반복이었다 — 어느 화면을 빠뜨렸는지 알 수 없다.

### 수정

- **`scripts/clone_run.sh`** (신규) — `observe` 와 `verify`. 두 명령이 clone 의 기계적 반쪽을 각각 닫는다. 사이에 남는 것은 스크립트가 소유할 수 없는 저작(화면 스펙 `.md`, SwiftUI 뷰)뿐이다.
- **`device_flow.py next-tap`** (신규) — 지금 할 탭 하나. 이 화면의 미탐험 후보가 우선, 없으면 미탐험 화면까지의 최단 관찰 경로 첫 홉. 좌표는 항상 건네받은 fresh 트리에서 다시 읽으므로 낡은 좌표 가드가 경로 홉에도 그대로 걸린다. 경로 홉은 이미 탭한 전이라 `todo` 가 제외하는 대상 — 그래서 두 번째 질의가 필요하고, 두 번째 서브시스템은 필요하지 않다.
- **`device_wda.sh explore`** — 루프의 질의를 `todo` → `next-tap` 으로 바꿨다. 이제 화면 사이를 스스로 옮겨 다니며, 종료는 전역 frontier 소진·max steps·`CLONE_EXPLORE_MAX_ROUTE`(기본 12) 연속 경로 홉이다.
- **`clone_flow_codegen.py`** — producer 가 실제로 쓰는 `statekey`/`from_statekey`/`to_statekey` 를 먼저 읽는다. 기존에는 underscored alias 만 읽어 조용히 coarse `node` 로 폴백했다(2026-08-16 lesson 과 같은 계열의 drift).
- **SKILL.md / commands/clone.md** — 기본 경로를 두 명령으로 재작성하고, 사람 게이트 4곳을 **삭제가 아니라 자율 기본값 + opt-in** 으로 바꿨다. CRITICAL RULE 9(진행을 사람에게 묻지 않는다) 추가.

### 검증

- `tests/test_device_flow.py` — `next-tap` 6 테스트(현재 화면 우선, 1홉·2홉 라우팅, 전역 소진, 도달 불가 시 탭을 지어내지 않음, 트리 부재 거부).

- `tests/test_clone_flow_codegen.py` — producer 필드명으로 manifest/전이가 state 단위를 유지하는지.
- `tests/test_clone_run.py` (신규) — 거절 경로와 state→view→측정 stem 조인.
- `scripts/verify_spec_docs.py` PASS, 전체 회귀 스위트 PASS.
- **실기기 end-to-end 는 수행하지 않았다** (기기 없음). "테스트 통과"가 한방 복제 실증은 아니다.
- `clone_skill_sync.py check` 는 여전히 drift 를 보고한다 — 설치된 0.13.10 패키지에 `clone_structural_diff.py` 가 이미 없었고(이번 변경 이전부터), 여기에 `clone_run.sh` 가 더해졌다. 스킬 문서만 sync 하면 안 되고, 일치하는 패키지를 재설치/reload 해야 한다(스킬 Step 0 규칙 그대로).

### 리뷰 후 추가 수정

- `clone_run.sh verify` 가 렌더 전에 **`views.json` 의 타입 중 `Sources/` 에 정의가 없는 것**을 먼저 이름으로 낸다. `device_render.sh` 는 Sources 를 한 덩어리로 컴파일하고 생성된 라우터가 모든 매핑 타입을 참조하므로, 뷰 하나를 안 쓰면 **모든** 화면 렌더가 실패한다 — 그 경우 24개의 동일한 컴파일 오류가 아니라 빠진 타입 목록을 준다.
- `next-tap` 이 "이 캡처 소진"과 "전역 소진"을 구분한다. `frontier` 는 한 state 의 모든 캡처의 후보를 합치므로(피드의 스크롤 위치), 현재 트리에 없다고 탐험이 끝난 게 아니다. 전자는 스크롤·재캡처 안내, 후자만 `frontier empty`.
- `_resolve_bundle_id` 가 무엇을 어떤 근거(exact-bundle / exact-name / sole-search-hit)로 해석했는지 로그에 남긴다 — 스킬 규칙 2(추정 금지)의 증거.
- SKILL Step 2c 정정: `views.json` 항목을 지우면 `generate` 가 실패한다. 범위 축소는 삭제가 아니라 자리표시자 뷰다.

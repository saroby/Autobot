# clone — flow 우선 재현 설계 (2026-07-25)

구현 완료. 이 문서는 **되돌리기 어려운 결정과 그 근거**를 남긴다. 절차 자체의 SSOT 는 `skills/autobot-clone-app/SKILL.md` 다.

## 문제

`/autobot:clone` 은 화면 하나를 측정해 SwiftUI 로 재현했다. 첫 독푸딩에서 드러난 것: 에이전트가 화면 2개를 **임의로** 골랐고, 그 화면이 앱에서 어떤 위치인지 모른 채 복제했다. 맥락 없는 재현은 껍데기다. 커버리지 지표가 없어 "후보 6개 중 1개만 탐험"이라는 사실조차 드러나지 않았다.

## 결정

### 1. flow 를 재현보다 먼저 (Step 2 → 2a → 2b → 2c → 3)

기존 측정→대조 단계(3~6)의 번호는 **바꾸지 않고** 앞에 2a/2b/2c 를 삽입했다. `commands/clone.md`·`device_render.sh`·기존 스펙 문서가 단계 번호를 인용하고 있어, 재번호는 교차 참조를 전부 깨뜨린다.

### 2. 화면 정체성을 두 개로 분리 — 이게 핵심 결정이다

| | `sig` (기존) | `nodekey` (신규) |
|---|---|---|
| 정의 | 라벨 집합 해시 | role 개수 버킷 + 내비바 제목 해시 |
| 민감도 | 어떤 라벨이 바뀌어도 변함 | 데이터 변화·스크롤 흡수 |
| 용도 | 탭 가드(화면이 움직였나) | flow 그래프 노드 |

**왜 하나로 안 되나**: 탭 가드는 민감해야 한다(화면이 조금이라도 바뀌면 낡은 좌표를 거부해야 함). 그래프 노드는 둔감해야 한다 — `sig` 로 노드를 세면 목록을 한 줄 스크롤할 때마다 새 노드가 생겨 **미방문 큐가 영원히 마르지 않는다.** 목적이 반대라 한 함수로 겸할 수 없다.

**버킷 폭의 근거**: 셀 개수를 `0/1/2/4/8/16/16+` 로 버킷한다. 한두 줄 스크롤은 흡수하되 **빈 상태(셀 0)와 채워진 상태(셀 5)는 다른 노드**로 남긴다 — 그 둘은 재현해야 할 서로 다른 레이아웃이므로 합쳐지면 안 된다.

**실기기 검증**: 세션을 새로 열고 같은 화면을 캡처했을 때 이전 세션과 동일한 `nodekey` 가 나왔다(`e78415336ffd`, `24de22e9c9d1`).

### 3. 전이 기록은 코드가 강제한다 (문서가 아니라)

이 레포에서 반복 확인된 사실: **코드로 만든 가드는 버티고 문서로 만든 가드는 뚫린다**(`tasks/lessons.md` 2026-07-25). 그래서 `device_wda.sh` 의 `screen`/`tap` 이 직접 `flow.jsonl` 에 쓴다. 기록 위치는 `CLONE_FLOW_LOG` 기본값으로 **고정**한다 — 호출자가 정하게 두면 `map` 이 읽을 곳을 알 수 없다.

**전환 대기(settle)가 필수인 이유**: `tap` 은 즉시 반환하고 화면은 애니메이션 중이다. 탭 직후 서명을 읽으면 **출발 화면이 도착지로 기록**되어 모든 엣지가 "제자리"가 된다(첫 독푸딩에서 수동 `sleep 1.5` 를 넣어야 했던 이유). 서명이 바뀔 때까지 폴링하고, 안 바뀌면 `changed=false` 로 남긴다 — "이 버튼은 아무 데도 안 간다"도 데이터다.

### 4. 중단이 정상, 재개가 1급 경로

실기기 탐험은 세션 만료(900초)·잠금·로그인 벽 중 하나에 반드시 걸린다. **완주가 예외다.** `flow.jsonl` 이 탐험의 전체 상태이므로 `device_flow.py next` 가 미방문 후보를 복원한다. 재개를 나중에 붙이는 기능이 아니라 루프 계약에 넣었다.

### 5. 역기획은 관찰과 해석을 물리적으로 분리

역기획은 전부 추론이고 실측 근거가 없다. 이 문서가 `/autobot:mvp` 입력이 되면 추측이 명세로 승격된다. 그래서 `## 관찰`(로그·측정에서 그대로) / `## 해석`(항목마다 근거 관찰 표시) 두 섹션을 강제한다. 동작 계약의 `미탐험` 표기, 커버리지 리포트와 같은 규칙의 세 번째 적용이다.

읽는 범위는 **flow 그래프 + 측정된 화면까지**. App Store 리뷰·평점은 `copy` 의 입력이다 — 끌어오면 방금 분리한 두 스킬 경계가 무너진다.

### 6. 데이터가 필요한 화면은 사용자에게 요청한다

읽기 전용으로는 빈 상태밖에 못 보는 지점이 있다. 세 선택지 중 **읽기 전용 + 필요 시 1회 요청**을 택했다(사용자 결정). 에이전트가 항목을 만들면 사용자의 실제 기기에 데이터가 남고, 삭제는 파괴적 라벨이라 되돌릴 수 없다. 거절하면 맵에 `데이터 필요` 로 남기고 넘어간다.

## 기각한 것

- **copy 를 호출해 역기획 받기** — 기기 탐험이 두 번 돌고, copy 산출물에 clone 이 결합된다. clone 이 자체 수행하고 초점을 달리했다(copy=왜 사랑받는가/리뷰 기반, clone=왜 이 배치인가/flow 기반).
- **copy 와 clone 병합** — 오늘 분리한 구조를 되돌리고 스킬이 비대해진다.
- **CLIP 유사도 지표** — 임베딩 모델이 필요해 무의존성 규칙(PNG 디코딩도 zlib 로 직접 짬)과 충돌. 대신 요소 누락 카운트를 검증 기준으로 넣었다(누락이 이 분야 지배적 실패 85.3%).
- **단계 전면 재번호** — 교차 참조가 전부 깨진다. 2a/2b/2c 삽입으로 대체.

## 남은 것

- `device_compare.py` 에 정량 지표 없음 — 재현본을 다시 측정해 원본과 요소 수를 자동 대조하는 커버리지 지표가 CLIP 보다 값어치 있다(누락이 지배적 실패이므로)
- 채워진 상태 재현 미검증(기기에 데이터 0개)
- `nodekey` 버킷 폭은 저널 앱 3화면에서만 검증 — 목록이 긴 앱에서 재확인 필요

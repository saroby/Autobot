# autobot-blueprint — 대상 서비스를 재구현 청사진으로

작성 2026-08-25 · 상태: 설계 승인 대기

## 왜

`/autobot:mvp` 는 `ssot/*.md` 를 읽어 앱을 만든다. `autobot-ssot` 은 그 문서를 **사용자 인터뷰**로 채운다. 비어 있는 입력원이 하나 있다 — **이미 존재하는 서비스를 관찰해서 채우는 것**.

원하는 프로세스는 셋으로 끝난다.

1. 대상 서비스를 관찰해 재구현 청사진을 만든다
2. 사람이 읽고, 부족하다고 생각하는 부분을 문서에서 고친다
3. 그 문서를 정본으로 앱을 (다시) 만든다

3번은 이미 돌아간다. 2번은 문서가 사람이 읽을 수 있어야 성립한다. **1번만 없다.**

**문서의 1번 목적은 사람이 파악하고 수정하는 것이다.** 기계 소비는 그 다음이다 — 이 순서가 뒤집히면 `observed/` 의 JSON 을 늘리는 쪽으로 설계가 흘러가고, 사람은 다시 못 읽는 문서를 받는다.

## 위치 — 충실도 스펙트럼

| | 관찰 | 산출물 | 의도 |
|---|---|---|---|
| ~~`/autobot:copy`~~ | iOS | 제품 브리프 1장 | **다른** 앱을 새로 |
| **`/autobot:blueprint`** | iOS · web | 청사진 7장 + 관찰물 | **같은** 서비스 + 개선 |
| `/autobot:clone` | iOS (web 설계됨·미구현) | 측정값 + 재현 코드 | **같은 화면** 그대로 |

`autobot-copy-analyze` 는 이 스킬에 흡수되고 `/autobot:copy` 는 `/autobot:blueprint` 로 라우팅 후 퇴역한다. 두 스킬이 같은 관찰 코드를 각자 부르며 드리프트하는 상황을 만들지 않기 위해서다. 이관 대상은 App Store 메타·리뷰 수집과 대상 확정 로직이다.

## 아키텍처

```
관찰 계층 ─ clone 과 공유 ─────────────────────────
  ios : device_wda.sh · device_flow.py          (기존)
  web : web_driver.py                            (clone-web 과 공유 · 신규)
        └ 공유 계약: references/clone-contract.md (신규 · 선행 조건)
공개 자료 ─ product·principles 에만 ───────────────
  App Store 설명 · 리뷰                          (copy-analyze 에서 이관)
                     ↓
observed/            기계 소유 · 매 회차 갱신
  flow.jsonl  screens/*.json  flow-map.html      기계가 읽는 증거
  raw/*.png                                      화면 이미지 (문서가 싣는 원본)
  inventory.md                                   화면 표 — 썸네일·진입 경로·나가는 전이
  vocabulary.md                                  화면 텍스트에서 뽑은 도메인 어휘
  public/*.md                                    공개 자료 발췌 (출처 표기)
  drift.md                                       지난 회차 대비 변화
                     ↓ 합성
ssot/                사람 소유 · 편집 대상 · 항목 단위 병합
  README · product · principles · features · domain · design · decisions
                     ↓ 사람이 "부족한 부분" 수정
/autobot:mvp         이미 ssot/ 를 읽는다 — 배선 불필요
```

관찰 소스는 iOS 실기기와 웹 브라우저 둘 다다. 공개 자료는 `product.md`·`principles.md` **에만** 쓴다 — 화면 구조에는 닿지 않게 가둬서 오염 위험을 좁힌다.

**재구현 대상은 관찰한 플랫폼 그대로다** (web→web, ios→iOS). clone 의 대각선 규칙과 같다. 웹 청사진의 재빌드를 받을 웹 빌더가 Autobot 에 아직 없으므로, 그 경로는 당분간 문서까지다.

## 관찰이 채우는 문서와 아닌 문서

| 문서 | 관찰 | 근거 |
|---|---|---|
| `features.md` | ○ | 화면·전이·액션이 곧 기능 목록 |
| `domain.md` | ○ | 화면 텍스트·라벨이 도메인 어휘, 반복 단위가 엔티티 |
| `design.md` | ○ | 색·타이포·간격이 측정값 |
| `product.md` | ✕ | 공개 자료로 채운다. 화면으로는 "왜 존재·대상 유저·성공 지표"를 알 수 없다 |
| `principles.md` | ✕ | 공개 자료로 채운다. "하지 않을 것"은 없는 화면이라 관찰 불가 |
| `decisions.md` | — | 우리 결정 로그. 관찰 무관 |

관찰로도 공개 자료로도 안 나오면 **"관찰·공개자료로 알 수 없음"을 명시하고 사람에게 넘긴다.** 그럴듯한 문장으로 메우지 않는다 — 관찰 없는 해석이 청사진 자리에 앉는 것이 이 스킬의 지배적 실패 모드다.

## 문서 계약 — 항목 구조

`ssot/` 의 모든 문서는 **항목으로 쪼갠다.** 산문 덩어리는 병합할 수 없고, 사람이 "뭐가 부족한가"를 훑기도 어렵다.

```markdown
## F-012 피드 무한 스크롤
근거: 관찰 · observed/inventory.md#feed
<img src="../observed/raw/03-feed.png" width="220">

스크롤 끝에서 다음 페이지를 불러온다. 로딩 중 스켈레톤 3개 표시.
```

- **ID** — 문서별 접두사(`F-` 기능, `E-` 엔티티, `D-` 디자인, `P-` 원칙, `V-` 제품). 병합의 키이고, 다른 문서가 참조하는 주소다.
- **근거 라벨** — 아래 네 값 중 하나. **라벨 없는 항목은 금지.**

  | 라벨 | 언제 붙나 | 누가 쓰나 |
  |---|---|---|
  | `관찰` | 실제로 본 것 — 화면·전이·측정값 | 기계 |
  | `공개자료` | App Store 설명·리뷰 등에서 나온 것 (`product`·`principles` 한정) | 기계 |
  | `가설(미검증)` | **관찰에서 추론했지만 확인하지 못한 것.** 라벨을 보고 "게시"로 짐작했으나 탭해보지 않은 동작 등. clone 의 동작 계약이 `미탐험` 행을 두는 것과 같다. **빈 문서를 메우는 용도가 아니다** — 근거가 될 관찰이 없으면 이 라벨도 쓰지 않고 "알 수 없음"으로 남긴다 | 기계 |
  | `우리 결정` | 사람이 넣거나 고친 것 | 사람 |

- **화면 이미지** — 근거가 된 화면을 항목이 직접 싣는다. `<img width="220">` 인라인 HTML 을 쓴다. 마크다운 `![]()` 는 폭 지정이 안 되고, 이 레포는 Pillow 없이 stdlib 만 쓰므로 **썸네일을 새로 만들지 않는다.** 원본 `observed/raw/*.png` 를 폭만 제한해 싣는다.

## 병합 규칙 — 근거 라벨이 소유권이다

`ssot/` 는 한 번 쓰고 마는 문서가 아니다. 대상은 계속 바뀌고 재관찰이 돌지만, **재관찰이 사람의 편집을 지우면 안 된다.** 파일 단위가 아니라 항목 단위로 가른다. 선례는 `cmd_codegen` 의 `views.json` 병합 — 이미 있는 이름은 유지하고 새 state 만 새 이름을 받는다.

| 근거 라벨 | 재관찰 시 |
|---|---|
| `관찰` | 기계가 갱신한다 |
| `공개자료` | 기계가 갱신한다 |
| `가설(미검증)` | 기계가 갱신한다 |
| `우리 결정` | **기계가 절대 건드리지 않는다.** 사람이 넣은 "부족한 부분"이 여기 산다 |

- 사람이 `관찰` 항목을 고치면 라벨을 `우리 결정` 으로 바꾼다 → 그 순간부터 보호된다. clone 의 `// Generated by` 를 지우면 손질본이 되는 경계와 같은 모델이다.
- 관찰에서 **사라진** `관찰` 항목은 지우지 않고 `관찰: 최근 회차에 없음` 을 붙인다. 지우면 그 항목을 근거로 삼은 사람의 결정이 붕 뜬다.
- 관찰이 `우리 결정` 항목과 **충돌하면** 지우지도 덮지도 않고 `⚠ 관찰이 다름: …` 을 그 항목 아래에 덧붙인다. 판단은 사람이 한다.
- 회차 간 변화는 `observed/drift.md` 에 모은다.

## 규칙

1. **관찰과 해석을 섞지 않는다** — 모든 항목은 근거 라벨을 갖는다. 라벨 없는 문장은 금지.
2. **못 채운 칸은 비운다** — 빈 파일·빈 헤딩 금지(`ssot` 기존 규칙)를 상속하되, 알 수 없는 것은 "알 수 없음"으로 남긴다. 추측으로 메우지 않는다.
3. **커버리지를 숨기지 않는다** — 부분 관찰은 부분이라고 말한다(clone 규칙 6 상속).
4. **사람의 편집을 덮지 않는다** — 위 병합 규칙.
5. **공개 자료는 `product`·`principles` 밖으로 나가지 않는다.**
6. **모든 화면 참조는 이미지를 동반한다** — 어느 화면인지 글로만 지시하지 않는다.

## 범위 밖 (YAGNI)

- **부족한 점 자동 제안** — 기계가 "이 서비스에 뭐가 부족한지" 판단하지 않는다. 사용자가 "부족하다고 **생각하는**" 것을 넣는 단계이고, 관찰만 한 제품에 대해 기계가 개선안을 쓰는 것은 근거 없는 주장이다.
- **웹 재빌드** — 웹 빌더가 생기면 그때.
- **로그인 벽 뒤 자동 돌파** — clone 과 같은 경계를 지킨다.

## 선행 조건

이 스킬은 아직 없는 것 둘에 의존한다. 둘 다 clone 작업에서 이미 설계된 항목이다.

1. `references/clone-contract.md` — 공유 관찰 계약(`flow.jsonl`·`screens/*.json` 스키마). 소비자가 clone·blueprint 둘이 되므로 여기서 값이 커진다.
2. `web_driver.py` — 웹 관찰 어댑터. `autobot-clone-web` 과 공유.

iOS 단독으로 먼저 출시하고 웹은 어댑터가 생긴 뒤 붙이는 순서도 가능하다. 그 경우 1번만 선행 조건이다.

## 분할 — 한 계획으로 하기엔 크다

구현 계획은 셋으로 나눈다. 각각 독립적으로 값을 내고, 앞이 없으면 뒤를 검증할 수 없다.

1. **문서 계약과 병합 엔진** — 항목 파서, 근거 라벨, 병합 규칙, 드리프트 리포트. 관찰 없이 픽스처로 전부 테스트된다. 여기가 이 스킬의 심장이고, 나머지는 이 계약에 데이터를 붓는 일이다.
2. **iOS 관찰 → 합성** — `copy-analyze` 이관, `observed/` 생성(`inventory.md`·`vocabulary.md`·이미지), `ssot/` 초안 합성.
3. **웹 관찰** — `web_driver.py` 가 생긴 뒤. 2번의 합성 코드를 그대로 재사용한다.

1번을 먼저 하는 이유는 오늘 clone 에서 얻은 교훈과 같다: 검증할 수단이 없으면 개선했는지 알 수 없다. 병합이 사람의 편집을 지키는지는 픽스처로 증명할 수 있고, 실기기 회차를 돌기 전에 증명해야 한다.
